# PDF 阅读（PDF Reader）

一页或多页并排阅读 PDF，右侧是整篇共用的对话：选中文字或框选图片即可提问，也可以标注、把内容输出成文件；需要更多原文时模型会自己翻阅。

## 入口

- 左侧栏底部的 **PDF 阅读** 图标（与插件、定时任务并列），点击进入中央阅读面板。
- 面板首次打开显示拖放区；点「打开 PDF」直接弹出 Windows 文件选择框（不可用时回退到内置弹窗，可粘贴完整路径），或把 PDF 拖进面板（拖入会保存到工作区 `.pdf-reader/` 下再打开）。
- 最近打开的文件会保留在空状态和文件选择框里。悬停条目右侧的垃圾桶图标可以删除该 PDF 的**全部对话记录**（PDF 文件和标注保留），删除前会在原地确认一次。

## 阅读

- **单页 / 连续两种视图**：顶部左侧的「单页」「连续」按钮切换。连续模式把所有页竖排显示，滚动时当前页自动跟随；单页模式一次一屏。`←` / `→` / `PageUp` / `PageDown` / `j` / `k` 翻页，顶部可以输入页码。单页模式下，页面已经滚到最上或最下时继续滚轮会直接翻到上一页 / 下一页：鼠标滚轮一格一页、没有冷却时间，触控板按滚动距离累积触发。
- 版面与缩放：点顶部的百分比打开菜单，可选 **适应宽度**、**适应页面**、**实际大小 100%**，或 50% / 75% / 125% / 150% / 200%；`+` / `−` 按步放大缩小；在页面上 `Ctrl`/`⌘` + 滚轮也能缩放。适应模式会随着窗口和对话栏宽度自动重算。
- 布局可拖动：阅读区和对话区之间的竖线可以左右拖（双击复位 390px，聚焦后 `←`/`→` 微调、`Home` 复位），宽度会记住；顶部对话图标可一键收起/展开对话，把整幅宽度让给 PDF。
- 每页按需渲染：连续模式下只加载视口附近的页，其余先占位；页面文本层覆盖在图片上，所以浏览器原生选中、复制都可用。
- 阅读进度、当前文档、页码、视图模式、对话栏宽度和对话都存在浏览器本地（localStorage），切换会话/面板后回来还在。

## 提问

- **框选提问（右键手势）**：在页面上**按住鼠标右键**拖动，拉出一个矩形；按住期间**滚轮可以继续翻页**，选区跟着光标延伸；最后**左键单击确认**（`Esc` 取消）。
  - 框选**以图片为主**：由 PyMuPDF 在服务端高分辨率裁剪，不提取矩形内的正文文字。适合图表、公式、扫描页、版面结构。
  - **范围内的标注会一起发送**：落在框里的高亮会按原色（半透明）画进裁剪图，标注的页码、颜色、原文和备注也会作为文字随消息发出；确认时的提示和消息标签会显示「含 N 条标注」。
  - 确认后引用标签为 `框选图片 第 2 页`，输入问题回车即可；跨页框选最多带 3 页裁剪图。当前模型不支持图片时，会提示切换视觉模型或改用左键选择文字。
- **文字提问（左键选择）**：用鼠标左键拖选文字，浮出 `问这段` / `解释` / `翻译`，只发送选中的文字及其页码。连续模式下可以跨页拖选，工具条会显示"问这 2 页"。
- **发送图片**：输入框左侧的图片按钮可以选图，也可以直接在输入框 **Ctrl+V 粘贴截图**，或把图片**拖进对话栏**。最多 3 张，自动缩放到 1600px 后随问题一起发送；需要当前模型支持视觉。发送后可以在消息里看到「附 N 张图片」。
- 输入框 `Enter` 发送、`Shift+Enter` 换行；发送中可随时停止。
- **让模型直接输出文件**：在提问里说「把第 10 页的内存要求整理成一份 md」「把这几页的对照表导出成 html」即可。模型会调用 `save_file`，把你要求的内容整理成完整正文写入工作区，回答下方会出现文件卡片（显示文件名，可复制完整路径）。
  - 支持 `.md` / `.txt` / `.html`；默认写工作区根目录，也可以在提问里指定子目录（如「保存到 exports 目录」）。
  - 同名文件自动加序号；单次上限 4MB。框选提问也能用（此时只提供保存文件这一项工具，仍以图片为回答依据）。
- **手动保存回答**：每条回答下方的「保存」可以把整条回答存成文件；先在回答里选中一段再点「保存」，则只存选中的那段。弹窗里可以直接修改要保存的正文，再选 Markdown（`.md`）、纯文本（`.txt`）或 HTML（`.html`）。默认写入工作区根目录（弹窗里会填好绝对路径，可改成子目录），同名文件自动加序号；保存成功后弹窗显示完整路径，可「复制路径」。
- 回答流式显示在右侧。

## 模型与思考强度

- 输入框右下角是模型按钮，显示当前模型与思考强度；点开可选择 **provider / 模型**，以及该模型支持的 **思考强度**（`off` / `low` / `high` / `max`，默认 `high`）。
- 列表与正常对话的模型选择器同源（Harness `modelCatalog`）：每个模型标注「视觉 / 文字」，思考强度选项按模型提供，不支持时显示"该模型不支持思考强度"。
- 选择保存在本地，下次打开沿用；只影响阅读面板里的问答，不改变主对话的会话级模型。
- 选中纯文字模型时，框选图片会自动退回文字模式并提示；思考强度随请求传给 `ctx.llm.stream`，回答下方可以展开「思考过程」，生成中会显示"思考中…"。

## 定位与跳转

- 回答里出现的 `第 3 页`（含 `第 3–5 页`）会渲染成蓝色可点击文字，鼠标悬浮时出现蓝色描边底色，点击直接跳到该页。
- 回答里用 `「…」` 引用的原文也可以点：会调用 PDF 全文检索，跳到首个命中页，并在原文位置高亮约 3 秒。
- 系统提示词要求模型按这两种写法标注位置（`第 N 页` / `「原文」`），所以正常回答里的定位点通常都能点。
- 检索由 PyMuPDF 在全部页面上完成；长引文先按完整短语匹配，找不到再退到较短前缀。

## 标注

- **手动标注**：左键选中文字 → 浮条里的「标注」→ 填备注、选颜色（黄 / 绿 / 蓝 / 粉 / 紫）→ 保存。正文上会显示半透明高亮，右上角小圆点可再次打开编辑或删除；备注可以留空只做高亮。
- **标注列表**：对话栏顶部「标注 N」打开列表，点条目跳到对应页并闪烁定位。
- **存储**：写在 PDF 同目录的 `<文件名>.annotations.json` 侧车文件里（页码、矩形、原文、备注、作者、颜色、时间），目录不可写时落到系统临时目录；换浏览器或重装 Harness 都不会丢。标注不写进 PDF 本体，所以普通阅读器看不到；但框选发送时颜色会画进裁剪图，模型能看到。
- **AI 也能标注**：直接说「把第 10 页内存的第一条要求标黄，备注写重点」，模型会用 `list_annotations` / `create_annotation` / `update_annotation` / `delete_annotation` 操作；它给出的 `quote` 会在该页检索并转成矩形，AI 改动会实时刷新列表。框选发送时，范围内的标注也会随图带上原文、备注和颜色。

## 上下文与对话

- **整篇 PDF 共用一条对话**：翻页不会切换或清空对话；每条消息记录提问时所在的页码。不同 PDF 之间彼此独立。
- **不以页为单位发上下文**：默认只发你**选中的文字**（附页码）和**框选/附带的图片**，不预加载整页原文。
  - 对话只带最近 8 轮，每轮上限 400 字（合计约 4000 字符）；
  - 页面原文不再占用默认上下文，只有模型主动查阅时才进入这一次请求。
- 对话栏下方会显示本次实际构成和估算字数，例如 `上下文：引用原文（第 16 页） · 整篇 5 轮 · 约 0.8k 字`。
- **模型自行决定要不要读原文**：每次提问都提供 `read_pages`（读取指定页，可读当前页/前后页/任意页）和 `search_document`（全文检索）两个工具。没选中文字时，模型会自己读当前页；对话前后不连贯时，它会自己看相邻页——查阅过程在回答下方显示「读取第 10、11 页」「搜索「内存」」，最多自动查阅 10 轮。
- **新建对话**：对话栏右上角的「＋」图标为整篇开一条空白记录，旧记录保留。点标题（`整篇 ...`）打开对话列表：切换、删除或在列表底部新建；每条对话用第一句提问自动命名，显示轮数、涉及页数和时间。每篇最多 12 条对话，每条最多 40 条消息。
- **界面**：用户消息靠右、助手回答是浅色卡片；复制 / 保存按钮悬停时显现。空对话不再显示引导文案和「总结本页 / 要点清单 / 翻译本页」按钮，输入区只保留附图片、模型和发送。
- 存储：浏览器 localStorage（键 `dsh.pdf-reader.v1`），旧版"每页一条对话"的数据会在加载时自动合并成整篇记录。

## 实现

- Host 半（`index.js`）在 Harness 的 web server 上注册 `/pdf-reader/*`：
  - `info` / `page`：交给常驻的 PyMuPDF 进程（`pdf_worker.py`）解析并渲染；文档从内存打开并复用，翻页不需要重新启动解释器，也不锁文件。
  - `browse` / `import`：工作区内的目录浏览与 PDF 导入（路径限制在工作区根目录内）。
  - `export`：把一条回答（或选中片段）写成 `.md` / `.txt` / `.html`；目录限制在工作区根目录内，同名自动加序号，单次上限 4MB。
  - `ask`：每条对话对应一个 DSH agent 会话（`pdfr-<文档hash>-<id>`），经 `sessionController.prompt()` 提交，回答通过 `agent/assistant-stream` 事件转成现有的 SSE 协议。每个 PDF 在 `.pdf-reader/docs/<hash>/` 下有独立的工作目录（agent 的 `cwd`，只存 `document.json` 指针，不复制原件）；`read_pages` / `search_document` / 标注 / `save_file` 作为该 agent 的作用域工具注册，系统提示词也按 agent 作用域挂载，不影响主对话。删除对话走 `agent/archive`，调用 `workspaceRegistry.archiveSession()` 归档。agent 运行时不可用时自动回退到直连 `ctx.llm.stream()` 的循环，保证面板可用。框选提问时，先把落在选区内的标注颜色画进裁剪图（`crop` 的 `marks`），再把标注的页码、颜色、原文、备注一起放进提示词。
- Client 半（`client.js`）注册 `sidebar.panellist`（`pdf-reader`）与 `main` 面板（`pdf-reader`），样式只使用 `--dsw-alias-*` 主题变量。

## 依赖与配置

- 需要本机 Python 3 且安装 PyMuPDF（`pip install pymupdf`）；默认调用 `python`，可用环境变量 `PDF_READER_PYTHON` 指定解释器。
- 可选环境变量：`PDF_READER_ROOTS`（用系统路径分隔符分隔的额外可读根目录）、`PDF_READER_PROVIDER` / `PDF_READER_MODEL`（覆盖默认模型）。
- 安装到另一台 DeepSeekHarness 的完整步骤见 [TRANSFER-SETUP.md](TRANSFER-SETUP.md)。
